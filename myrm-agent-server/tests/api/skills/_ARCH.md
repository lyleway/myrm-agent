# tests/api/skills/

## 架构概述

技能 API 的路由与响应测试集。本清单登记下列文件，目录内其余测试文件未在此登记。

## 文件清单

| 文件 | 地位 | 职责 | I/O/P |
|------|------|------|-------|
| `test_discovery_install_refusals.py` | 测试 | 安装接口的拒绝响应（拒绝由真实安装门禁产生，只有注册表拉取与替换快照入口被替身）：技能名带孤立代理字符（含同时带路径分隔符的名字）时，`/install` 与 `/install-from-url` 返回 200 的失败结果，错误码与错误文案同门禁一致，技能名里的孤立代理字符显示为 `U+FFFD` | ✅ |
| `test_discovery_response_encoding.py` | 测试 | 发现响应的文字编码：注册表条目的文字带孤立代理字符时 `/search` 返回 200，孤立代理字符显示为 `U+FFFD`、其余文字不变；每个携带注册表、包或扫描器文字的响应模型，其每个文字字段（普通、可选、列表）校验时都修复孤立代理字符，新增字段漏掉修复会在这里失败 | ✅ |

| `test_growth_skill_reference.py` | 测试 | 后台复盘结果按它被看到的名字找技能（名字由产品自己的 `skill_to_runtime_metadata` 生成，技能来自真实本地扫描）：被锁技能的补丁以列表名到来也落成 `BLOCKED_LOCKED`、草稿名是目录名（目录名带连字符、不带连字符，SKILL.md 名含大写、带引号、长于 64 个字符，五种写法各一例）；未锁技能的补丁以列表名到来落成待审核草稿、批准后落到该技能且不新建目录；目录名与 SKILL.md 里的名字不同的技能，按两种名字都能找到；两个技能的列表名相同不猜（目录名仍精确命中）；与已有技能列表名相同的新技能草稿落成待审核草稿、名字不改、不在旁边建出重复目录；长过目录项能有的长度的名字落成待审核草稿而不是被丢弃；大小写不敏感的卷上拼写不同的名字（`report-builder` 对目录 `Report-Builder`）也找到被锁技能（补丁与草稿各一）、不被自动覆盖且批准后返回的 id 是已有技能的页面 id、目录旁有失效的符号链接时仍能找到（这几例在大小写敏感的卷上跳过）；任何卷上，新技能草稿只在批准它会写进已有技能的目录时才记成目录名（判据是批准写入的名字，即清洗后的名字：记成目录名 ⟺ 批准后返回的 id 是已有技能的页面 id ⟺ 已有技能的 SKILL.md 被改写；目录 `report-builder`、SKILL.md 名与草稿名是 `Report-Builder`、`Report Builder`、`Report-Builder.` 时，大小写不敏感的卷上记目录名、批准原地更新，大小写敏感的卷上名字不变、批准在旁边建出新目录且已有技能不动；`report builder` 与 `report-builder-` 在任何卷上都写进 `report-builder`；含 Kelvin 符号的名字与经主技能目录绕回该目录的路径写不进它，任何卷上都不改名）；`approval_writes_into` 对目录自己的名字、清洗后落到该目录的写法（空格、句号、首尾空白、结尾连字符、含 NUL）、另一个目录、没有对应条目、Kelvin 符号与长 s 冒充的字母、经主技能目录绕回该目录的路径与该目录的绝对路径各给出该卷的答案；已有技能的 SKILL.md 名是这样一条路径、草稿同名时，批准不改写已有技能；技能在列主技能目录时已被删掉，按查找时的名字原样返回 | ✅ |
| `test_growth_fixture_routes.py` | 测试 | 「批准技能草稿」Chrome E2E 用的三个本地夹具路由：非本地模式下三个路由都是 404 且不动已有目录；目录名不是一个路径分量（含 `..` 的相对路径、带斜杠、点开头、空、连字符开头、64 个字符、含空格）在写入或删除之前就被拒；播种写出 SKILL.md 名与目录名可不同的技能、返回的页面 id 与「卷是否忽略大小写」与实际一致、目录已存在为 409 且原内容不动；清理只删主技能目录直接子级里的真实目录，符号链接（指向目录外的目录不动）、普通文件、不存在的名字都跳过且不计入返回；复盘结果以 `skill_draft` 类型、测试给的智能体与技能名交给生产的 `process_skill_review_result`，返回是否记成了草稿 | ✅ |
| `test_evolution_fixture_route.py` | 测试 | 「批准进化提案」Chrome E2E 用的本地夹具路由：非本地模式为 404、技能目录不存在为 404，两种情况都不记提案；记下的提案是针对磁盘上那份 SKILL.md 的待审提案（`PENDING_REVIEW`/`NOT_APPLIED`，技能页面 id 与路由返回一致，路径与原文取自文件），生产的 `apply_content_update` 能把它落到文件上，原有步骤与追加的步骤都在；请求里的 `agent_id` 就是提案所属的智能体，没有 `owner_agent_id` 时不碰进化库；给了 `owner_agent_id` 时进化库里存的是带 `scope_agent_id` 的该技能，另一个智能体来批准时 `apply_content_update` 走 fork：生成 `fork_` 开头的新技能与 `-fork` 目录，所有者的文件原样不动；路由去掉非本地模式的拒绝、写错追加的步骤、忽略 `agent_id` 或不存所有者，对应用例失败 | ✅ |
