# tests/unit/ai_agents/media_tools 模块架构

媒体生成工具（`app/ai_agents/media_tools/`）的单元测试目录：图像、视频、语音三个工具的行为与参数契约，媒体生成交付契约，落库回调，引用解析策略，以及产物的工作区副本（复制、接线、文件夹被换成链接时的写入边界）；媒体库用真实的内存 SQLite 与本地存储，只替换供应商调用。

## 文件清单

| 文件 | 地位 | 职责 |
|------|------|------|
| `test_image_agent_tool.py` | 模块 | `image_tool`：工厂返回命名的工具，schema 只含官方参数，schema 之外的值在做任何事之前就被拒；`list` 返回目录与已选模型；`generate` 要求 prompt、每张图启动一个任务，没有任务存储时明确报错而不退回同步；`edit` 经唯一的解析器取图与蒙版、把给定的 `quality` 交给引擎、端到端读媒体库里的图、请求不完整时不调引擎并点名无法使用的引用；别的动作的参数被拒绝而不是丢弃，空白参数算没写；`status` 要求 task_id，如实报告未知任务与不可用的存储，已完成的任务返回存下的结果，失败的任务告诉模型下一步 |
| `test_video_agent_tool.py` | 模块 | `video_tool`：工厂返回命名的工具，schema 没有 force 标志也没有未知的供应商名；`list` 列出已注册的供应商；`generate` 要求 prompt、带着收到的全部参数启动一个任务，没有任务存储时明确报错，供应商没有的参数照样交给引擎去报告；未知动作被拒；`status` 对已完成的视频返回存下的引用，如实报告未知任务与缺失的 id；schema 去掉供应商用不上的参数，没有能力信息时保留全部参数 |
| `test_status_wait.py` | 模块 | 等待媒体任务：`status` 带 `wait_seconds` 时任务一结束就答、不晚于所问的时限（不等待时立即答；已结束的任务不等待；失败与取消结束等待，失败带下一步；到时限给出最后的状态，最后一次睡眠被截到剩余的时间；等待中被删的任务按未找到报告，存储消失明确报错，取消调用即停止等待）；两个工具的 `status` 照做，范围外的等待在查任务之前被拒，schema 与描述交代了等待，图像工具拒绝其他动作带等待；每个视频供应商的 schema 都提供等待，`generate` 的答复告诉模型怎样对待运行中的任务；时钟与睡眠被替换，没有测试真的在等 |
| `test_image_clamp.py` | 单元 | `clamp_image_payload`：空字节与坏图优雅降级，小图无损直通，超限的边被缩小，RGBA 合成到干净的 RGB，EXIF 方向烘焙进像素；每张解析出的图都经这唯一的一道限幅：媒体库引用与工作区文件引用都在送出前被限幅 |
| `test_tts_agent_tool.py` | 模块 | `tts_generate`：工厂返回命名的工具且只支持异步；成功的结果带存下的引用、供应商与模型；没有存下的引用即错误，引擎失败如实报告，空文本与超长文本被拒，`style` 去空白并限长后才到引擎；结果点名音频在工作区的副本，没有工作区的智能体得到原样的结果，生成失败不动工作区，复制失败时结果保持原样并说明 |
| `test_media_generation_contract.py` | 模块 | 媒体生成交付契约（读 `shared/config/media_generation_contract.json`，前端读同一份）：每个示例符合其形状且检查能抓到改名或未落库的字段；客户端的图像模型就是引擎目录；生成调用返回已启动的任务（两种工具）、完成的图片与视频任务、同步改图与语音调用的结果都落在契约形状上；聊天登记的条目与共享用例一致；真实的工作区复制器给三种结果加上的字段必须是各自形状声明过的，错类型的字段会被检查抓到 |
| `test_workspace_export.py` | 模块 | 工作区副本（真实媒体库）：与存下的文件逐字节一致且是复制不是链接，重复调用不重写也不覆盖用户改过的副本，并发只留一份完整文件且无临时文件，同一结果的每个引用按序只复制一次，首次复制记一条日志、重复不记；`_generated/` 在 git 里自我忽略（临时仓库里 `git status` 与 `git add -A` 后暂存区都为空），用户自己的同名目录不动，`.gitignore` 写不进时目录不留（规则已建出而写入失败时连规则一起撤销），并发的另一次调用先写好的 `.gitignore` 照用，规则写入失败时并发调用已放进目录的 `.gitignore` 与副本原样保留；能指向别的路径的 id、未知条目、文件已丢、存储键逃出存储根、非本地存储、没有可用扩展名、工作区缺失或不可写、复制写到一半失败都如实报错且不留半截文件，能复制的与不能复制的并列；没人预见的异常记日志并报告而不让调用失败，取消不被吞掉；一个智能体的工作区是它声明的第一个目录，没有目录就没有复制器 |
| `test_workspace_export_confinement.py` | 模块 | 工作区副本的文件夹不是出口（真实媒体库；换链接在指定的步骤里注入，结果不取决于时机）：`_generated` 本来就是链接时被拒、链接目标不变，本来是文件时如实报错、文件不变；文件夹刚打开或刚创建、第一次写入之前，或拷贝字节途中，被换成指向工作区外的链接：链接目标里已有的 `.gitignore` 字节不变、没有新文件，被换走的目录里没有临时文件，错误记入 `workspace_files_error`；经链接到达的工作区与相对路径的工作区照常复制 |
| `test_workspace_export_wiring.py` | 模块 | 图像与视频工具把产物放进工作区（语音工具的同类用例在 `test_tts_agent_tool.py`）：已成功任务的 `status`（含等待结束的那次）与同步 `edit` 的结果带 `workspace_files`；用户或聊天不同的任务（含一方没有聊天）不产生文件也不带字段，两边都没有聊天算同一信任域，没成功的任务与任务记录本身不被改动；没有工作区的智能体与引擎返回的错误都原样返回，复制失败时主结果不变并带 `workspace_files_error`；三个工具的说明都交代了字段与它缺省的含义，发给模型的工具文本不随工作区、用户、聊天变化；结果里的 `./_generated/<id>.<扩展名>` 路径不被凭据脱敏当成随机密钥遮掉（40 个随机 id 经 `redact_leaks` 后与原文逐字相同，改成不带 `./` 的写法即失败） |
| `test_masked_edit_source.py` | 模块 | 带蒙版的编辑不缩小原图（真实媒体库、解析器、验证器，只替换供应商调用）：3000×2000 的 JPEG 原样到达供应商且与蒙版同尺寸，EXIF=6 的 4000×3000 转正为 3000×4000 且不缩小，蒙版原样到达；超过引擎上限的原图得到验证器的明确错误且不调供应商；无蒙版的编辑照旧缩到 2048 px 以内，带蒙版时会超限的同一张图在无蒙版时被缩到能通过 |
| `test_media_persist.py` | 模块 | 图 / 视频 / 语音引擎共用的落库回调：存下的图返回其引用并保留提示词与模型；没有聊天的后台作业同样落库；聊天 id 去空白后才关联会话；引擎给的模型优先、回调的模型只做兜底；音频无分辨率；存储失败抛错且不留记录 |
| `test_input_policy.py` | 单元 | 工具与任务执行器共用的引用解析策略：媒体引用读媒体库并缩小图片，工作区文件夹的可读范围，只有本地部署可访问私网；工作区外的路径被拒，媒体库缺项时指出字段名；只净化不缩小的钩子让大图原样通过、仍把带 EXIF 旋转的图转正、仍把透明合成到白底，且除图片钩子外与原策略相同 |
