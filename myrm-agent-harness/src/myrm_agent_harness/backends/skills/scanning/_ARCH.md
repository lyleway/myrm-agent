# scanning/

## Overview
Skill content security scanning — regex patterns, Python AST analysis, package manifest audit, dependency extraction, offline known-compromised package advisories matching, OSV.dev vulnerability intelligence (batch advisory lookup, full-record severity, CVSS v3 scoring) with TTL caching, advisory acknowledgment governance, LLM semantic audit, and secure ZIP extraction. `scan_skill_content` memoizes per exact content (see `backends/skills/_content_memo.py`).

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Re-exports scanning APIs for agent and backend consumers. | — |
| ast_analyzer.py | Core | AST-level Python security analysis (eval, subprocess, pickle, etc.). A syntax error yields an `info` `ast_parse_error` finding (the file cannot run); source the parser or the tree walk cannot take at all (nested or chained too deeply, unencodable text) yields a `high` one next to the findings made before the failure, so a file the analysis is blind to never reads as clean and the scan never raises on it. | ✅ |
| archive_security.py | Core | Canonical archive security contract (error code/message), executable signature detection, and structured logs/metrics. | ✅ |
| cvss.py | Core | CVSS v3.x base score computed from an OSV vector string (v4 and malformed vectors yield `None`). | ✅ |
| dependency_extractor.py | Core | Manifest and lockfile dependency extractor for package.json (npm), requirements.txt (PyPI), pyproject.toml (PyPI), uv.lock (PyPI), bun.lock (npm; JSONC, resolved registry versions only), and package-lock.json (npm). One dispatch by file name serves the in-memory scan of an archive and the disk scan of a directory. The disk scan reads the files `tree_walk.py` finds (any depth, every folder but `node_modules`; a symbolic link is not followed), reads each through a bounded text read (a file over 16,777,216 characters is skipped with a warning), and logs a part of the tree the walk could not examine as an incomplete scan. | ✅ |
| llm_auditor.py | Core | LLM-based semantic threat detection beyond regex/AST coverage. Parses the finding object via `parse_llm_json_object` (robust against fences, prose, bare control chars, trailing commas). | ✅ |
| osv_scanner.py | Core | Online OSV.dev vulnerability intelligence scanner: the batch endpoint (100 queries per request) yields advisory ids only, so each unique advisory's full record is fetched once for its severity (database label, else CVSS v3 base score, else MEDIUM; `MAL-*` is CRITICAL; an unpinned dependency's findings are capped at MEDIUM; a bare lockfile version such as `312` counts as pinned) and text. Requests run with bounded concurrency and retry transient failures; whatever still cannot be queried is logged as a warning and the scan fails open; only fully resolved dependencies are cached; `resolve_severity=False` skips the record requests for latency-bound callers. | ✅ |
| package_audit.py | Core | package.json supply-chain audit: the lifecycle scripts a bare `npm install` runs (`preinstall`, `install`, `postinstall`, `prepublish`, `preprepare`, `prepare`, `postprepare`) are high findings, suspicious commands in any script medium; the files a package manager runs at install without any declared script (`binding.gyp`, `.npm-extension.cjs`/`.mjs`, `.pnpmfile.cjs`/`.mjs`, matched in any case, a symlink included) are high findings too; `check_lifecycle_scripts` is the in-memory gate over an archive and `audit_skill_directory` the disk gate, with the same checks; entry point artifacts are checked for physical reachability and non-empty integrity (the `exports` walk is iterative, a name the file system rejects is a missing artifact). One reader takes every manifest the way the installers do (one leading BOM skipped, a repeated key refused, at most 1,048,576 characters read); a manifest it cannot take (invalid JSON, a repeated key, nesting or an integer the parser cannot take, over the character limit), a symlinked `package.json` and one that cannot be read are each one high `invalid_manifest` finding, so such a manifest never reads as clean and the audit raises nothing on a manifest's content. The disk gate walks the tree through `tree_walk.py`, so a manifest at any depth in any folder but `node_modules` is audited, and what it cannot look at in full is one high `invalid_manifest` finding as well: a folder it cannot list, a tree of more than 100,000 entries, and the manifest after the first 100. A finding quotes what the package controls and travels in responses, so its constructor makes every text UTF-8 encodable (a lone surrogate becomes `U+FFFD`) and cuts the description and the detail to 500 characters. | ✅ |
| patterns/ | Core | 技能安全扫描模式子包：injection/exfiltration/filesystem/network/system 五组纯数据 + types；`__init__` 按原顺序汇总 `ALL_PATTERN_GROUPS`。详见 [patterns/_ARCH.md](patterns/_ARCH.md) | ✅ |
| rescan_engine.py | Core | Installed skill multi-layer rescan orchestrator with AdvisoryAckRegistry governance and auto-quarantine disposition. | ✅ |
| scanner.py | Core | Single-content scanner (regex patterns, invisible Unicode, Python AST), its result types, scan summary aggregation and report formatting. `scan_skill_content` is memoized per (skill name, extension, exact content): a hit returns a fresh `ScanResult` copy, and a result with more than 128 findings is never pinned. | ✅ |
| directory_scanner.py | Core | Multi-file skill directory scan with file-count, file-size and wall-clock limits; each file goes through the memoized `scan_skill_content`. | ✅ |
| security_advisories.py | Core | Offline known-compromised package advisories catalog for zero-latency, deterministic detection of notorious malware. | ✅ |
| tree_walk.py | Core | Bounded breadth-first walk over the files of a skill directory, shared by the two disk readers of package manifests (`package_audit.py`, `dependency_extractor.py`): no depth cap, only `node_modules` is not entered, a symbolic link is yielded as one and never followed, and every entry counts against a 100,000-entry budget (one folder is never read past it). A folder it cannot list, an entry it cannot examine and a tree over the budget are yielded as a `WalkProblem`, so a caller never takes a partial look for a complete one. | ✅ |
| vuln_cache.py | Core | Vulnerability scan result cache with 24-hour TTL and disk persistence. | ✅ |
| zip_extract.py | Core | Secure ZIP extraction (compression ratio / entry-count / total-size limits, symlink/path traversal defense, executable-binary rejection). | ✅ |
| scanning_write_backend.py | Core | Framework-level security wrapper that enforces mandatory scanning before skill writes. | ✅ |
| path_security.py | Core | Filesystem path security (symlinks, Windows directory junctions) and category bucket collision defense (GitHub Issue #75983). | ✅ |
