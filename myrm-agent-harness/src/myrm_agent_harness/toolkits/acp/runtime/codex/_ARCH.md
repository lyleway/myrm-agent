# codex/

## Overview
Codex runtime backend — keeps one `codex app-server` process per backend and drives it over its JSON-RPC protocol on stdin/stdout: a thread per conversation, a turn per prompt, the host's approval policy and sandbox set with every turn, approvals answered by the person the turn belongs to, images by path, usage as per-step deltas, stop, and resume from the rollouts Codex keeps on disk.

Detailed design: [ACP_SYSTEM.md](../../ACP_SYSTEM.md)

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Facade: lazy `CodexRuntime`. The other modules are imported by their own path. | ✅ |
| approvals.py | Core | `ApprovalResponder`: the answers to the server's requests. A command, a file change, an extra permission or an MCP tool call that needs approval becomes a `PermissionRequest` for the turn's broker (the patch of a file change is shown as a bounded excerpt of each change), and the verdict goes back as accept or decline; a request still waiting when the turn is stopped is answered cancel, which ends the turn. Where nobody can answer (no broker, or `allow_all` under which Codex asks for nothing) every request is declined and logged (`codex_approval_refused`). A question for the user at the Codex screen gets no answer, and a tool call gets none because the host registers no tools of its own. | ✅ |
| connection.py | Core | `AppServerConnection`: one started and greeted server process — its environment (`server_environment`: the safe base environment of every runtime, and in `api_key` mode the configured provider key taken out of it and handed to the server by its login, since every command and MCP server the agent starts would inherit it), spawning through `../process.py`, the handshake (`initialize` then `initialized`), the in-memory login of an API key (`account/login/start`), and a graceful or immediate stop. Never reused after it ended. | ✅ |
| failure.py | Core | `classify_turn_error`: the `AcpError` of a failed turn from the structured error the server attaches (`codexErrorInfo`: a category, or a category with the HTTP status); a refused login (401) is `AUTH_FAILED`, a 403 is not a login problem; a rate limit is `RATE_LIMITED`; an overloaded or failing server is marked retryable; `is_auth_rejection` tells a retry notice that carries a 401. No failure is guessed from its wording. | ✅ |
| items.py | Core | `ItemBook` and `file_changes`: the items of a turn seen so far, which `turn_events` (what an item is doing) and `approvals` (what a request is about: the request names only the item, the item holds the patch) both read. | ✅ |
| protocol.py | Core | What the host says: `initialize_params` (client identity and the notification methods it opts out of), `login_params`, `config_read_params`, `turn_policy` (the approval policy and sandbox of a mode: `safe` with somebody to ask is Codex's Read Only preset — `on-request` with a read-only sandbox, so reads run silently and a write, the network or a patch is asked; `safe` with nobody to ask is `never` with a read-only sandbox; `allow_all` is `never` with the user's own workspace-write settings read through `config/read`), and the requests that open a thread and run a turn (`thread_params`, `resume_params`, `turn_params`). Checked against the schema the installed Codex generates by the real-binary contract tests. | ✅ |
| rpc.py | Core | `JsonRpcPeer`: requests out with their own timeouts, notifications and server requests in; params of a request are never logged (a login request carries an API key); every message is one ASCII line, so no text in it can break the framing. | ✅ |
| runtime.py | Core | `CodexRuntime`: starts the server on the first turn and again after it was lost, opens or resumes the conversation's thread, runs the turn under the policy of the turn's permission mode, says `working` every 15 s of silence, gives up a turn after 3 consecutive 401 retries, stops a turn with `turn/interrupt` (a waiting approval is cancelled at once), reports a missing program once as `BACKEND_NOT_FOUND`, and ends the turn with DONE or the one classified ERROR; a server that went away mid-turn fails that turn and is started again by the next. | ✅ |
| threads.py | Core | `ThreadBook`: which thread a harness session is on and how it is found again — recorded in memory and written through to the host's `CliSessionStore` when there is one, so a new server process or host process resumes the rollout Codex keeps on disk; without a store the threads are ephemeral and leave nothing in the user's Codex history. A conversation recorded for another directory, or one the server no longer knows, continues as a fresh thread and the turn says why (`session_workspace_changed`, `session_expired`). | ✅ |
| turn_events.py | Core | `TurnTranslator`: the notifications of one turn told to the host as `RuntimeEvent`s — pure translation without I/O. Notifications of another turn (a late one of an interrupted turn included) are ignored; a message that starts after earlier text is set apart by a blank line; an item that streamed its text is not repeated when it completes; the retry notices of a rejected login are counted (`auth_rejection` after 3). | ✅ |
| usage.py | Core | `UsageMeter`: the running totals of a thread turned into the step each model request cost, so a repeated report adds nothing and a thread resumed after a restart does not bill its history to the turn. | ✅ |
| wire.py | Core | Typed reads (`as_obj`, `as_list`, `as_str`, `as_bool`) of the decoded JSON the server sends: a field that is missing, null or another type after an upgrade reads as nothing there and never raises inside the turn loop. | ✅ |
