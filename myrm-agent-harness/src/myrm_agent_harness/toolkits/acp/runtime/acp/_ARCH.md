# acp/

## Overview
ACP runtime backend — keeps one external ACP-compatible agent process per backend (Claude Code, Codex CLI, ...) and drives it over the ACP JSON-RPC protocol on stdin/stdout: session reuse, resume, cancel, permission requests, file access with path safety, image prompts, and a bounded stop for an agent that stopped reading.

Detailed design: [ACP_SYSTEM.md](../../ACP_SYSTEM.md)

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Facade: lazy `AcpRuntime`. The other modules are imported by their own path. | ✅ |
| callback.py | Core | ACP callback handler for the AcpRuntime backend: it answers the agent's `session/request_permission` through `AcpPermissionPolicy` (typed `RequestPermissionResponse`, the agent's own option ids) and serves the agent's file callbacks truthfully — `read_text_file` returns the file's strict UTF-8 text (a line window when asked) and a missing, unreadable or non-UTF-8 file is a JSON-RPC error, never an error string passed off as content; `write_text_file` writes bytes, so an agent that reads a file and writes it back leaves every line ending (CRLF, lone CR) as it was, and in `safe` mode asks the host about each file before the first write. | ✅ |
| permission_policy.py | Core | `AcpPermissionPolicy`: who answers an ACP agent's permission requests for one turn. `allow_all` accepts everything; in `safe` mode a read, search or think request is accepted and everything else is put to the turn's `PermissionBroker` as a `PermissionRequest` (tool, kind, title, input, the real paths of the call), with the host's session id rather than the agent's own. A file the host allowed to be edited is remembered for the turn, so the agent's own write callback for it is not asked about again. With no broker (an unattended turn) everything but reading is refused and logged as `acp_permission_refused_unattended`. The answer is always one of the options the agent offered: an `allow_once` / `allow_always` for a yes, a `reject_*` for a no, and a cancellation only when the agent offered no option of the kind that was needed. | ✅ |
| runtime.py | Core | ACP protocol runtime backend — session reuse, cancel, resume; a prompt failure re-raises to surface as ERROR once the turn's events have been consumed to the end, and is only logged at INFO (`acp_prompt_task_failed_after_close`) when the consumer closed the turn first (a stop that ended the agent), so closing never turns into an error; `session/close` is sent only when `initialize` advertised `sessionCapabilities.close` and is bounded (4s), so a silent agent cannot skip the transport teardown that terminates its process; an agent that stays silent is reported as `working` every `KEEPALIVE_SECONDS`, and a missing ACP SDK (the optional `acp` extra) ends the turn with one named `BACKEND_NOT_FOUND` error that says how to install it. Turn images are sent as ACP image content blocks after the text block, only when `initialize` advertised `promptCapabilities.image` (an agent without it gets the text alone, an INFO log and an `images_not_sent` status update). A known agent is started by its contract (`resolve_acp_args`: the entry flag and `--approval-mode default`, without the flags that let it skip asking such as `--yolo` or `--approval-mode`), a WARNING `acp_approval_flags_dropped` names what was dropped, and in `safe` mode the mode `session/new` reports must be the one that asks (`AuthProfile.acp_ask_mode`): another is reset with `session/set_mode` (WARNING `acp_session_mode_reset`) and an agent that cannot be put in it ends the turn with an error, so the host's policy is the only one that answers its permission requests. A refused login (`session/new` failing with the ACP `auth_required` code, -32000) ends the turn as `AUTH_FAILED` with the agent's own words. A stop never waits for an agent that has stopped reading its stdin: `cancel` and the transport exit go through `stalled_agent`. | ✅ |
| stalled_agent.py | Internal | Bounded stop of an ACP agent that has stopped reading its stdin: a large prompt stuck in the pipe queues `session/cancel` and the SDK's transport exit behind itself, and the SDK's sender swallows the cancellation of a wait on it, so `cancel_session` and `leave_transport` wait at most `STALLED_AGENT_TIMEOUT_SECONDS` (5s) and then `end_agent` ends the agent and every process it started (the SDK spawns the agent in the host's own process group, which must not be signalled, so `code_execution/session/process_tree.py` walks the tree process by process). Releasing the agent's pipes is what fails the stuck write and frees the queue; ending the agent alone would leave its tools running and, when one inherited the agent's stdin, the write stuck. A healthy agent never reaches the bound. | ✅ |
