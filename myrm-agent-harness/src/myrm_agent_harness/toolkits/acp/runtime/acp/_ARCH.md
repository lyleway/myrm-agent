# acp/

## Overview
ACP runtime backend — keeps one external ACP-compatible agent process per backend (Gemini CLI, Qwen Code, ...) and drives it over the ACP JSON-RPC protocol on stdin/stdout: session reuse, resume, cancel, permission requests, file access with path safety, image prompts, and a bounded stop for an agent that stopped reading.

Detailed design: [ACP_SYSTEM.md](../../ACP_SYSTEM.md)

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Facade: lazy `AcpRuntime`. The other modules are imported by their own path. | ✅ |
| capabilities.py | Core | `AgentCapabilities`: what an ACP agent said it can do in `initialize` (image prompts, HTTP MCP servers, `session/load`, `session/resume`, `session/close`); everything it did not advertise is False. The runtime decides by this record alone and never asks an agent for what it did not advertise (Gemini 0.71.1 answers `session/resume` with "method not found"); a capability enters the record together with the code that acts on it. | ✅ |
| callback.py | Core | ACP callback handler for the AcpRuntime backend: it answers the agent's `session/request_permission` through `AcpPermissionPolicy` (typed `RequestPermissionResponse`, the agent's own option ids) and serves the agent's file writes truthfully — `write_text_file` writes bytes, so what the agent writes is what lands on disk (every line ending, CRLF and lone CR included), refuses a path outside the workspace with a JSON-RPC error and, in `safe` mode, asks the host about each file before the first write. Messages the agent streams on either side of a tool call are set apart by one blank line (`paragraph_break`), and what the agent sent before `begin_turn` (the history a loaded session replays) is dropped there, so the turn's output is only what the turn said; `begin_turn` also hands the turn's read-only MCP server names to the policy. It offers no file reads (`client_capabilities()` says so in `initialize`): the agent shares the host's disk, and Gemini (0.71.1) takes the error that says a file does not exist for a failure and then cannot create a new file at all. | ✅ |
| mcp_origin.py | Core | `mcp_server_of`: which of the MCP servers a host handed an agent a tool call belongs to, as the agent says it in the `_meta` of its permission request (ACP has no field for it). Gemini names the server (`_meta["gemini-cli"]["mcp"]["server_name"]`); Qwen names the tool `mcp__<server>__<tool>` (`_meta["toolName"]`), unambiguous because a server's name never holds `__`. A call that names none of the declared servers (an agent's own tool, an agent whose `_meta` says nothing, opencode as far as checked) has no origin. Both forms are those of the real Gemini 0.71 and Qwen 0.28, held by `tests/toolkits/acp/test_real_http_mcp.py`. | ✅ |
| permission_policy.py | Core | `AcpPermissionPolicy`: who answers an ACP agent's permission requests for one turn. `allow_all` accepts everything; in `safe` mode a read, search or think request is accepted, and so is a request the agent says belongs to an MCP server the host declared `read_only` for this turn (`begin_turn(…, read_only_servers)`, `mcp_origin.py`), and everything else is put to the turn's `PermissionBroker` as a `PermissionRequest` (tool, kind, title, input, the real paths of the call), with the host's session id rather than the agent's own. A file the host allowed to be edited is remembered for the turn, so the agent's own write callback for it is not asked about again. With no broker (an unattended turn) everything but reading is refused and logged as `acp_permission_refused_unattended`. A request that still waits for a person when the turn ends or is cancelled is withdrawn (`end_turn`) and answered with the cancelled outcome, which ACP asks of a cancelling client and which an agent waiting for the answer needs before it ends its prompt. The answer is always one of the options the agent offered: an `allow_once` / `allow_always` for a yes, a `reject_*` for a no, and a cancellation only when the agent offered no option of the kind that was needed. | ✅ |
| runtime.py | Core | ACP protocol runtime backend — one ACP session per harness session (`sessions.py`: continued across an agent or host restart, and every event carries the host's session id, never the agent's), cancel (which first answers the permission requests still waiting as cancelled, then sends `session/cancel`), resume; a prompt failure re-raises to surface as ERROR once the turn's events have been consumed to the end, and is only logged at INFO (`acp_prompt_task_failed_after_close`) when the consumer closed the turn first (a stop that ended the agent), so closing never turns into an error; `session/close` is sent, for every session the agent holds, only when `initialize` advertised `sessionCapabilities.close` and is bounded (4s), so a silent agent cannot skip the transport teardown that terminates its process; an agent that stays silent is reported as `working` every `KEEPALIVE_SECONDS`, and a missing ACP SDK (the optional `acp` extra) ends the turn with one named `BACKEND_NOT_FOUND` error that says how to install it. Turn images are sent as ACP image content blocks after the text block, only when `initialize` advertised `promptCapabilities.image` (an agent without it gets the text alone, an INFO log and an `images_not_sent` status update). A turn's MCP servers go to `session/new` through `sessions.py`; an agent that advertised no `mcpCapabilities.http` runs without the HTTP ones, which every turn names in an `mcp_not_attached` status update, and the names of the servers declared `read_only` go to the permission policy for the turn. A known agent is started by its contract (`resolve_acp_args`: the entry flag and `--approval-mode default`, without the flags that let it skip asking such as `--yolo` or `--approval-mode`), a WARNING `acp_approval_flags_dropped` names what was dropped, and in `safe` mode the mode `session/new` reports must be the one that asks (`AuthProfile.acp_ask_mode`): another is reset with `session/set_mode` (WARNING `acp_session_mode_reset`) and an agent that cannot be put in it ends the turn with an error, so the host's policy is the only one that answers its permission requests. A refused login (`session/new` failing with the ACP `auth_required` code, -32000) ends the turn as `AUTH_FAILED` with the agent's own words. A turn ends with a `DONE` event carrying the agent's own `stop_reason` (`StopReason`), and the host decides what each one means. A stop never waits for an agent that has stopped reading its stdin: `cancel` and the transport exit go through `stalled_agent`. | ✅ |
| sessions.py | Core | `AgentSessions`: which ACP session the running agent holds for each harness session, and how a conversation is given back. A new agent process or host process continues the recorded conversation from the agent's own storage — `session/resume` when the agent advertised it (Qwen 0.28.6: no replay), else `session/load` (Gemini 0.71.1: replays the history as updates, which `begin_turn` drops), else a fresh session. A session the agent no longer knows (any JSON-RPC error but `auth_required`) is replaced by a fresh one and the turn opens with a `session_expired` notice; a conversation recorded in another folder starts fresh with `session_workspace_changed`; a refused login ends the turn as `AUTH_FAILED` and the record is kept. The record is written through to the host's `CliSessionStore` (via `CliSessionBook`) only for an agent that advertised resume or load, since an agent that advertised neither has nothing to give back. `acp_mcp_servers` turns a turn's MCP servers into the servers a session opens with: a stdio server for any agent, an HTTP one (URL and headers) only for an agent that advertised `mcpCapabilities.http`; the names left out are kept with the session and reported by every turn. | ✅ |
| stalled_agent.py | Internal | Bounded stop of an ACP agent that has stopped reading its stdin: a large prompt stuck in the pipe queues `session/cancel` and the SDK's transport exit behind itself, and the SDK's sender swallows the cancellation of a wait on it, so `cancel_session` and `leave_transport` wait at most `STALLED_AGENT_TIMEOUT_SECONDS` (5s) and then `end_agent` ends the agent and every process it started (the SDK spawns the agent in the host's own process group, which must not be signalled, so `code_execution/session/process_tree.py` walks the tree process by process). Releasing the agent's pipes is what fails the stuck write and frees the queue; ending the agent alone would leave its tools running and, when one inherited the agent's stdin, the write stuck. A healthy agent never reaches the bound. | ✅ |
