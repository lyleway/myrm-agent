# runtime/

## Overview
ACP Runtime backends — unified interface for the agents the host delegates to: ACP agents (Gemini, Qwen), CLI agents (Claude Code) and the agent with an app server of its own (Codex).

## File & Submodule Index

| __init__.py | Package | ACP Runtime backends — unified interface for ACP, CLI and app-server agents. | ✅ |
| _base.py | Internal | Base class for RuntimeBackend implementations — timeout control, truncation, error handling (`_classify_failure` lets a runtime name a failure it knows, such as a refused login, before the generic one is reported); `build_safe_env` gives a child process only the core variables (shared `CORE` policy of `core/security/process_env/env_isolation.py`) plus the variables that relocate its CLI's login home, then the configured `env` by `auth_mode`, then the home of the account it runs as (`RuntimeConfig.account_home`, last so the provider-prefixed home variables of Gemini and Qwen survive the subscription filter), then `NODE_USE_SYSTEM_CA=1` while enterprise network compatibility is on (`infra/tls_compat.py::with_node_system_ca`; a value from `env` wins) — `CliRuntime`, `AcpRuntime` and `CodexRuntime` all spawn with it; the turn generator is closed with `aclosing`, so a timeout, a failure or an abandoned stream stops the backend process; `KEEPALIVE_SECONDS` and `working_status` are the silence heartbeat the runtimes share; `UNAUTHORIZED_RETRIES_LIMIT` is the number of consecutive retries of a request answered 401 after which a turn is given up. `run_turn(permissions=...)` wraps the caller's `PermissionBroker` as the turn's `TurnPermissions`, bound to the turn's time limit. | ✅ |

Leaf module. | ✅ |
| process.py | Core | `ManagedProcess` / `spawn_managed_process`: one agent process group for every runtime that starts one — line-wise stdout (16 MiB line limit), bounded stderr tail, and the only code that stops it (idempotent SIGTERM→SIGKILL, shielded from caller cancellation, runs on every exit path of the context). `start_prompt` encodes the prompt at once and writes it to stdin in a task beside the turn (closed when written; ended by `close`), so a CLI that has not started reading stdin (Claude reads stream-json input only after its start hooks) neither holds the turn nor its stop; `send` writes one line to a process that is driven line by line. `lines(idle_tick)` also yields `None` after each silent period, cancellation-safe (a partly read line stays buffered). `wait()` takes the exit code from the transport (asyncio's `Process.wait()` resolves only after every pipe closed, which a grandchild holding stderr delays) and bounds the stderr drain. | session_book.py | Core | `CliSessionBook`: bounded memory-first records of the agent-native conversation a harness session resumes (a Claude session id, a Codex thread id, an ACP session id), with best-effort write-through to the host `CliSessionStore` (contract and `CliSessionRecord` live in `types.py`); store failures degrade to a fresh session and never fail a turn. | ✅ |
| turn_permissions.py | Core | `TurnPermissions`: the one door through which a turn asks its host for permission. While a question is open the turn's time limit stands still (a person reading a prompt is not a hung agent) and the time left is given back after the answer; a question still open when the turn ends (a stop, a timeout of the time that remains) is cancelled and answered as a refusal; a broker that raises refuses the request and logs `permission_broker_failed`, so a failing host never lets an action through. | ✅ |
| mcp_status.py | Core | `mcp_not_attached_event`: the status update (`mcp_not_attached`, `servers`) that tells a host which of the MCP servers it offered a turn the agent was not given (a backend that does not take MCP servers, an ACP agent that advertised no HTTP MCP, a CLI that is not Claude Code), so the answer is not mistaken for one that had them. Leaf module. | ✅ |
| image_blocks.py | Core | `load_image_blocks`: the image files of a turn as `ImageBlock`s (media type + base64) in order, for both runtimes (a CLI stdin message block, an ACP image content block); the format comes from the file's first bytes via the shared `utils/mime_types.detect_image_mime`, kept to `VISION_IMAGE_MIME_TYPES` (PNG, JPEG, GIF, WebP), never its name; an unreadable or non-image file is skipped with an `image_skipped` WARNING that does not name the path. Blocking I/O: both runtimes call it in a thread. | ✅ |
| pool.py | Core | Runtime pool: multi-backend management with backends keyed by (name, workspace) (the caller names each turn's workspace; one agent in two directories has two backends, and the pool never infers a directory), concurrency control (global semaphore + per-backend serialization), config MCP passthrough gated by backend `supports_mcp` capability (a backend without it gets `None`, and the turn opens with an `mcp_not_attached` status update naming the servers), and per-turn `images` (local image files) gated by `supports_images` the same way (a backend without it gets `None` and the turn opens with an `images_not_sent` status update). Running turns are registered by (name, session id), which is what `cancel` and `close_all` reach; a `oneshot` turn runs on a private backend (fresh session, closed afterwards), so it never touches the shared backend's persistent session or process. `release_resident()` stops only the resident (ACP and app-server) backends and keeps CLI backends with their `--resume` ids, so a host can reclaim idle processes without ending CLI sessions (a Codex or ACP conversation continues from the agent's own storage when the host supplied a session store). `run_turn(permissions=...)` hands the turn's `PermissionBroker` to the backend. An optional `cli_session_store` is handed only to the shared persistent backends (never to oneshot private backends), so CLI, Codex and ACP conversations also survive a restart of the host process (and, for the resident ones, of the agent). `register` applies `effective_transport`: a command that exactly is a known agent runs over the transport its contract names (Gemini and Qwen over ACP, Claude Code per turn, Codex over its app server) whatever type its config stored, logged at INFO as `pool_transport_by_contract`, while any other command keeps the configured transport. No periodic liveness supervision: a resident ACP or app-server process that exited is reconnected by its next `run_turn`, and a CLI backend has no process between turns by design. | ✅ |
