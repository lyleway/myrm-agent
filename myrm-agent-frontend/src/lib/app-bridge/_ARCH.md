# app-bridge/ 模块架构

## 架构概述

沙箱应用页与宿主之间的通道与权限模型。页面没有网络与系统访问，`window.myrm.notify` / `fetch` / `llm.complete` / `tray` / `shortcut` / `float` 以 JSON-RPC 2.0 经 `postMessage` 发给宿主；宿主先确认发送者、再看放行状态与限速、最后代办；宿主用 `myrm/event` 通知页面（权限被收回、按下了登记的组合键）。后三项作用于应用窗口周围的操作系统，只在应用自己的桌面窗口里存在，别处一律 `unsupported`。页面的声明写在它自己的 HTML 里，用户的决定按能力存储，连同当时所见的范围（站点、组合键）与版本。

## 文件清单

| 文件             | 地位 | 职责                                                                                                                                                                                                                                                                     | I/O/P |
| ---------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----- |
| `protocol.ts`    | 核心 | 线上契约：能力词汇（含只在桌面窗口存在的三项；`ai` 的提示词、系统文本与输出上限与服务端同一组上限）、JSON-RPC 信封与宿主到页面的事件、失败原因（页面看到的稳定 `reason`）、各方法的参数校验；只有带 id 的 JSON-RPC 2.0 请求算「我们的消息」，主题、尺寸、存储消息共用同一信道但不被误认                                                                        | ✅    |
| `declaration.ts` | 核心 | 声明解析（HTML 里 `<script type="application/json" id="myrm-app">`，解析是惰性的）与权限状态：声明里没见过的能力或超出已批准范围的主机为「待询问」，已有决定在声明仍落在其范围内时继续生效；主机名只接受精确公网名，与服务端规则一致，用户读到的清单就是服务端强制的清单 | ✅    |
| `accelerator.ts` | 核心 | 全局组合键的唯一规则：至少一个 Shift 之外的修饰键，主键为 A-Z / 0-9 / F1-F12，每个应用至多 4 个，规范拼写唯一；服务端与桌面壳按同一条规则校验，用户在对话框里读到的组合键就是被注册的那个 | ✅    |
| `callLimiter.ts` | 核心 | 每项能力一个滑动窗口限速（`notify` 5 / `fetch` 120 / `ai` 40 / `tray` 30 / `shortcut` 20 / `float` 30 次每分钟），窗口内第一次拒绝单独标出，使日志每窗口只记一条 | ✅    |
| `externalScripts.ts` | 辅助 | 列出页面从其它站点加载的脚本及是否被锁住（`integrity` 哈希或地址里的精确版本才算锁住，浮动地址不算），供对话框提示「权限只覆盖这一版页面，不覆盖远程脚本之后的变化」；只提示不拦截 | ✅    |
| `shim.ts`        | 核心 | 页面侧 `window.myrm` 客户端（注入到页面 HTML 最前）；回复只认来自父窗口的消息；只是便利层，宿主自己鉴别发送者，不用它的页面什么也得不到                                                                                                                                  | ✅    |
| `hostTypes.ts`   | 辅助 | 只有类型：宿主拿到什么（`AppBridgeDeps`：状态读取、两个代发、桌面面）、回报什么（活动、`ProxyFetch*`、`ProxyAi*`）、交出什么（`AppBridgeHost`）；与 `host.ts` 分开，依赖方向一眼可见 | ✅    |
| `host.ts`        | 核心 | 宿主侧请求处理：限速（见 `callLimiter.ts`；`notify` / `fetch` / `ai` 的数字高于服务端自己的限额，由服务端对放行的调用做最终裁决）、状态闸门、参数校验，然后弹通知、经服务端代发请求或模型调用（服务端的 `permission_denied` / `budget_exceeded` / `unavailable` 等拒绝原因原样映射给页面，未知原因一律 `failed`），或在桌面窗口里接上托盘项、全局组合键与置顶；组合键只接受页面声明过且用户放行过的；`revoke` 与 `dispose` 撤掉页面登记在桌面上的内容；每次拒绝与出错记入活动记录（超限每窗口只记一条）；发送者的识别由调用方负责 | ✅    |
| `__tests__/`     | 测试 | 各文件的行为：信封与参数边界、声明与状态推导（含组合键与桌面能力）、页面客户端的往返、事件与外来来源、限速与失败映射、组合键规则、脚本锁定判断、桌面面（`hostHarness.ts` 放宿主的共用搭建） | ✅    |

## 依赖

- 不依赖项目内其他模块，只有目录内部引用：`declaration.ts` → `protocol.ts`、`accelerator.ts`；`protocol.ts` → `accelerator.ts`；`host.ts` → `protocol.ts`、`hostTypes.ts`、`callLimiter.ts`；`hostTypes.ts` → `protocol.ts`、`declaration.ts`（仅类型）；`shim.ts` 不引用任何模块
- `host.ts` 需要的代发请求、模型调用、系统通知、桌面面（托盘 / 组合键 / 置顶）、放行状态读取与活动记录，都由调用方经 `AppBridgeDeps` 注入

## 约束

- 不新增第二套桥：新能力 = 新方法名 + 声明项 + 状态推导
- `ai` 不带任何范围：它只能用页面自己给的文字做一次纯补全，花费由服务端按应用与用户总预算封顶；页面拿到的回答是不受信文本
- 页面 CSP 的 `connect-src` 保持 `'none'`：网络只经宿主代发，服务端在解析后拒绝私网地址
- 页面 CSP 的 `img-src` 仍允许任意来源（`*`）：页面可以用图片请求带出数据，所以任何文案都不得说「页面只能访问声明的站点」，只能说「页面的请求由宿主代发」
- 组合键规则只此一份（`accelerator.ts`），服务端 `capabilities.py` 与桌面壳 `app_surface/accelerator.rs` 按同一条规则校验
