# app-bridge/ 模块架构

## 架构概述

沙箱应用页与宿主之间的通道与权限模型。页面没有网络与系统访问，`window.myrm.notify` / `window.myrm.fetch` 以 JSON-RPC 2.0 经 `postMessage` 发给宿主；宿主先确认发送者、再看放行状态与限速、最后代办。页面的声明写在它自己的 HTML 里，用户的决定按能力存储，连同当时所见的范围与版本。

## 文件清单

| 文件             | 地位 | 职责                                                                                                                                                                                                                                                                     | I/O/P |
| ---------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----- |
| `protocol.ts`    | 核心 | 线上契约：能力词汇、JSON-RPC 信封、失败原因（页面看到的稳定 `reason`）、`notify` / `fetch` 的参数校验；只有带 id 的 JSON-RPC 2.0 请求算「我们的消息」，主题、尺寸、存储消息共用同一信道但不被误认                                                                        | ✅    |
| `declaration.ts` | 核心 | 声明解析（HTML 里 `<script type="application/json" id="myrm-app">`，解析是惰性的）与权限状态：声明里没见过的能力或超出已批准范围的主机为「待询问」，已有决定在声明仍落在其范围内时继续生效；主机名只接受精确公网名，与服务端规则一致，用户读到的清单就是服务端强制的清单 | ✅    |
| `shim.ts`        | 核心 | 页面侧 `window.myrm` 客户端（注入到页面 HTML 最前）；回复只认来自父窗口的消息；只是便利层，宿主自己鉴别发送者，不用它的页面什么也得不到                                                                                                                                  | ✅    |
| `host.ts`        | 核心 | 宿主侧请求处理：限速（`notify` 5 次 / 分钟，`fetch` 120 次 / 分钟，高于服务端自己的限额，由服务端对放行的调用做最终裁决）、状态闸门、参数校验，然后弹通知或经服务端代发请求；每次拒绝与出错记入活动记录（超限每窗口只记一条）；发送者的识别由调用方负责                  | ✅    |
| `__tests__/`     | 测试 | 各文件的行为：信封与参数边界、声明与状态推导、页面客户端的往返与外来来源、限速与失败映射                                                                                                                                                                                 | ✅    |

## 依赖

- 不依赖项目内其他模块，只有目录内部引用：`declaration.ts` → `protocol.ts`；`host.ts` → `protocol.ts`、`declaration.ts`（仅类型）；`protocol.ts` 与 `shim.ts` 不引用任何模块
- `host.ts` 需要的代发请求、系统通知、放行状态读取与活动记录，都由调用方经 `AppBridgeDeps` 注入

## 约束

- 不新增第二套桥：新能力 = 新方法名 + 声明项 + 状态推导
- 页面 CSP 的 `connect-src` 保持 `'none'`：网络只经宿主代发，服务端在解析后拒绝私网地址
