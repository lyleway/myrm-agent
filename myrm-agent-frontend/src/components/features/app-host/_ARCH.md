# app-host/ 模块架构

## 架构概述

已安装应用的宿主侧：应用是用户安装的 HTML 工件，运行在与普通 HTML 工件相同的沙箱 iframe 里（只有脚本、没有网络），宿主页在外层承载它、注入 `window.myrm` 客户端，并只替用户已放行的能力代办（通知、联网，以及只在应用自己的桌面窗口里存在的托盘项、全局快捷键、浮窗置顶）。权限在宿主页上决定：页面在自己的 HTML 里声明需要什么，用户逐项放行，放行按版本与声明范围生效；对话框同时写明审查与来源方面权限说不了的事。通道与权限模型见 [`@/lib/app-bridge`](../../../lib/app-bridge/_ARCH.md)，注册表与代办请求见服务端 `artifact_apps`。

## 依赖

- `@/lib/app-bridge` — 通道、声明解析、权限状态
- `@/services/artifactApps`、`@/store/useArtifactAppsStore` — 注册表与代办请求的 HTTP 客户端、安装状态
- `@/components/features/artifacts/renderers/MediaPreview::HtmlPreview` — 带主题与存储桥的沙箱 iframe
- `@/hooks/tauri/useIsAppWindow`、`@/lib/desktop/{appWindow,appSurface,appLauncher}` — 桌面应用窗口的识别、窗口控制、托盘 / 快捷键 / 置顶与启动器
- `@/lib/app-manifest` — 本应用的 PWA manifest 地址

## 约束

- 应用页本身不得获得 IPC 或网络：能力只经 `window.myrm` 到宿主，由宿主与服务端再校验一遍
- 授权文案逐项写明数据去向（会发通知、会访问哪些主机名、会占用哪些组合键），不展示技术细节
- 桌面能力只在应用自己的桌面窗口里询问与生效；网页端与会话窗口里页面声明了也不列出、不存储，并说明原因
